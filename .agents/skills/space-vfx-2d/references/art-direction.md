# 美术方向 · Cinematic 2D Deep Space

本文件定义**颜色、层级、节奏与外观**的统一语言。任何特效实现都要回到这里取 token，不要在实现文件里就地发明颜色或时长。

---

## 1. 视觉定位

一句话：**幽暗、精密、有力量感的宇宙；高等文明改变空间本身，星光偏移，深色半透明织物般的明暗结构柔和起伏、拉伸、收缩并恢复。**

正式引力视觉按 `SKILL.md` §8：星空形变 → 明暗褶皱 → 交互空间波动 → 节点光晕与拖尾；粒子仅用于适合的天体。本文保留的“已实现”描述属于原作者记录，当前 checkout 接口需按 SKILL.md §4 核对。

要的是：

- 幽暗而广阔的宇宙，深蓝近黑为底，不是纯黑。
- 精致、柔和、有层次的发光体——靠**叠加的透明层**做出来，不是靠 `shadowBlur`。
- 星空形变优先；粒子只用于太阳、虫洞、黑洞等合适的天体特效，持续汇聚 / 扩散的场粒子已弃用。
- 高等文明的力场让局部空间产生明暗变化（吸引处更暗更紧，排斥处更亮更散）。
- 飞船运动有自然连续的拖尾。
- 巨大的太阳、危险的黑洞、绚丽但不喧宾夺主的星云。
- 清晰克制的科幻 HUD。
- 所有运动都时间连续——没有跳变、没有逐帧重随机的闪烁。

明确**不要**的：网页渐变卡片审美、到处荧光边框、太多规则圆环/虚线/同心圆、教科书式引力线、过度 bloom 导致失去辨识度、大量粒子遮蔽飞船与危险天体、纯装饰性随机闪光、与真实物体运动不对应的视觉反馈。

整体气质是**克制、神秘、精密**，而不是花哨的科技演示界面。

## 2. 颜色系统

### 2.1 原稿 token（核对当前 `src/render/palette.ts` 后复用，不复制到别处）

| 用途 | Token | 值 |
| --- | --- | --- |
| 背景底 | `BG` | `#0c1220` |
| 吸引（P1，蓝） | `ATTRACT` | `#409eff` |
| 排斥（P2，金） | `REPEL` | `#e9bd48` |
| 行星亮/中/暗 | `PLANET_LIT` / `PLANET_BASE` / `PLANET_DARK` | `#a583cc` / `#8f69b9` / `#3b2b52` |
| 陨石本体/坑/边 | `ROCK_BASE` / `ROCK_CRATER` / `ROCK_RIM` | `#8993a3` / `#6f7885` / `#aab3c0` |
| 空间港 / 虫洞 | `STATION` / `STATION_SOFT` / `WORMHOLE_INNER` | `#64d98b` / `#9de3b3` / `#64d98b66` |
| 恒星核心/中 | `STAR_CORE` / `STAR_MID` | `#fff6d8` / `#f0cf7a` |
| 黑洞吞噬盘 | `VOID` | `#110a22` |
| 飞船船体 | `SHIP_HULL` | `#ffffff` |
| 文字 / 次级文字 | `TEXT` / `TEXT_DIM` | `#e5eaf4` / `#92a0b3` |
| 危险警告 | `HUD_WARN` | `#ff9a9a` |

**铁律**：`fillStyle` / `strokeStyle` 只接受 `palette.ts` 里的模块常量。绘制路径里**不拼 `rgba(...)` 模板、不拼十六进制**——每帧字符串插值会分配，渲染每秒跑 60 次。固定 alpha 写进 8 位十六进制（`#rrggbbaa`）；动态明暗用 `globalAlpha` 乘缓存核与时间包络，绘制后 restore，不能每帧拼颜色。

### 2.2 token 与历史实验标记

`ATTRACT_P` / `REPEL_P` 及 `ATTRACT_PULSE` / `REPEL_PULSE` 为 **Deprecated / Rejected Experiment** 的记录，不用于正式场特效。其他光晕 / 星云 token 保留；新增明暗缓存核用不透明近黑 / 低饱和亮色 token（例如 `SPACETIME_DARK='#060a14ff'`、`SPACETIME_LIGHT='#9fb6d8ff'`），透明度仅由 §9 统一合成后的标量与核决定，避免重复乘低 alpha。

粒子按**亮度档位**预分桶，每桶一个常量，这样整批粒子只需要每桶一次 `fillStyle` + 一次 `fill()`（与粒子数无关，详见 `performance-and-qa.md`）。四个档位对应粒子的四个生命阶段。

```ts
// 吸引粒子（冷色，最亮处接近白）
export const ATTRACT_P = ['#dcecff80', '#7cb8ff5c', '#409eff3d', '#1f5fa824'] as const;
// 排斥粒子（暖色）
export const REPEL_P   = ['#fff4cf80', '#f7d97e5c', '#e9bd483d', '#9c7a1f24'] as const;

// 节点光晕（外层向内叠加，加法混合）
export const ATTRACT_HALO = ['#409eff2e', '#409eff1f', '#409eff0f'] as const;
export const REPEL_HALO   = ['#e9bd482e', '#e9bd481f', '#e9bd480f'] as const;
// 节点核心白热
export const ATTRACT_CORE = '#e8f2ffff';
export const REPEL_CORE   = '#fff8e2ff';

// 激活脉冲环
export const ATTRACT_PULSE = '#409eff4d';
export const REPEL_PULSE   = '#e9bd484d';

// 星云（极低对比度，加法混合）
export const NEBULA_A = '#3b4a8c14';
export const NEBULA_B = '#6a3f7a12';
export const NEBULA_C = '#1f6b6b10';

// 局部空间扭曲：吸引处压暗、排斥处提亮
export const WARP_DARKEN = '#060a14';
export const WARP_LIGHTEN = '#9fb6d80f';
```

> `#rrggbbaa` 里 `80`≈50%、`5c`≈36%、`3d`≈24%、`24`≈14%、`2e`≈18%、`1f`≈12%、`0f`≈6%。改 alpha 就改这一位，不要改成 `rgba()` 调用。

### 2.3 光的三个来源

只用这三种，不要引入第四种：

1. **径向渐变**（`createRadialGradient`）—— 天体、节点光晕、星云。**必须缓存**，见 `celestial.ts` 的 `gradient()` 模式（key 按 kind + 量化半径，坐标建在原点，绘制前 `translate`）。
2. **加法混合**（`globalCompositeOperation = 'lighter'`）—— 粒子、光晕、星云、飞船尾迹。**玩家节点尾迹例外**，必须 `source-over`，否则 P1/P2 交叉处身份色被冲淡（见 `trail.ts` 的 `playerTrailStyle`）。
3. **分层透明**—— 明暗层次靠叠 2–3 层不同半径/alpha 的渐变，不靠模糊。

**不要 `shadowBlur`**：昂贵、并且会把所有东西推向霓虹感，与本作气质相反。

## 3. 亮度阶梯（画面层级）

同一屏幕上所有发光元素必须落在这个阶梯上，否则会出现"背景比飞船亮"这类抢读问题。

| 层 | 内容 | 目标峰值 alpha | 混合 |
| --- | --- | --- | --- |
| L0 | 背景底色 `BG` | 1.0（不透明） | source-over |
| L1 | 星云 | ≤ 0.14 | lighter |
| L2 | 程序化星空 | ≤ 0.55（最亮桶） | source-over |
| L3 | 时空明暗褶皱（背景层） | 压暗 ≤ 0.10 / 提亮 ≤ 0.06，事件已含在内 | source-over |
| L4 | 场范围提示（仅 ready/paused 虚线环） | ≤ 0.10 | source-over |
| L5 | 预测虚线 | 1.0（保持现状） | source-over |
| L6 | 尾迹 | ≤ 0.55 | lighter / 玩家 source-over |
| L7 | 天体本体 | 1.0 | source-over |
| L8 | 玩家节点 + 光晕 | 光晕 ≤ 0.18，本体 1.0 | lighter / source-over |
| L9 | 飞船船体 | 1.0（纯白，不透明） | source-over |
| L10 | HUD / 边缘箭头 / 小地图 | 1.0 | source-over |

**不可违反**：L9（飞船）与 L7（危险天体轮廓）在任何情况下都必须是画面里最锐利、最不透明的元素。任何特效果 alpha 超过 0.55 且覆盖到它们，就算失败。

## 4. 控制节点（蓝球 / 金球）

节点是"高维文明投射到二维空间的引力场控制节点"，**不是实体天体**：不碰撞、不被推动、不参与物理。

### 4.1 本体（几何不可改）

- 本体实心圆半径 = `player.radius`，**不得改动**。它是场的原点与玩家的定位锚点。
- 颜色严格 = `ATTRACT` / `REPEL`。这是全局身份约定，不许换色、不许做渐变本体。
- 标签 `P1 [F]` / `P2 [Enter]` 与开关状态文字保持现状。

### 4.2 光晕（新增，向外叠加三层）

从内到外，半径按本体半径 `r` 计：

| 层 | 半径 | 颜色 | 峰值 alpha |
| --- | --- | --- | --- |
| 内 | 2.2 r | `ATTRACT_HALO[0]` | 0.18 |
| 中 | 3.6 r | `ATTRACT_HALO[1]` | 0.12 → 0 |
| 外 | 5.5 r | `ATTRACT_HALO[2]` | 0.06 → 0 |

用**缓存的**径向渐变（`0 → 峰值 → 0`，stop 位置 0 / 0.35 / 1），加法混合。金球同构，用 `REPEL_HALO`。

### 4.3 核心

一个 `0.42 r` 的白热点（`ATTRACT_CORE`），alpha 0.55。**只有中心这一个亮点**——不要在节点内部撒星点，那是装饰性随机闪光。

### 4.4 内部能量运动

节点光晕是身份与定位辅助，不以显眼的周期呼吸或旋转瓣覆盖整个场范围。既有节点本体几何、身份色与 Trail 不变；有需要可保留很低幅度的本体质感变化，但空间层的起伏统一读取 `gravity-field-vfx.md` §9 的扰动模型。稳态安静，强反馈由交互触发。

---

### 4.5 拖尾

节点移动有与速度相关的自然拖尾，复用既有的 `Trail` 环形缓冲（`src/render/trail.ts`），样式用 `playerTrailStyle(polarity, spec)`。**不要另写一套**。

### 4.6 激活反馈

技能开启、快速移动节点、场强明显变化 → 短暂柔和的空间波动。基础形变让蓝球收缩、金球扩张；事件同时影响星点和明暗，传播的是状态变化的视觉消息。**不画细描边圆环，不按固定周期重播启动动画。**

建立约 90 ms，指数衰减起始时间常数约 0.85 s，末尾平滑归零；持续按住后趋于稳定。关闭场时基础形变和明暗缓慢恢复，不突然撤去整块盘。细节、参数与定容限频见 `gravity-field-vfx.md` §9–10。

这些是艺术化传播扰动，不是广义相对论引力波，不改变真实力、物理时间或技能规则。

## 5. 飞船视觉语言

飞船是全画面最需要保持可读性的对象。

### 5.1 现有形状

`celestial.ts` 的 `ship()`：白色三角（`8,0 → -6,-5 → -6,5`），朝向 = `atan2(velocity.y, velocity.x)`。保持不透明白，保持锐利；可以加同路径 `SHIP_EDGE` 描边（现状 0.5 alpha）。

### 5.2 三个方向必须分开

这是最容易做错的地方：

| 概念 | 来源 | 用途 |
| --- | --- | --- |
| **运动方向** | `body.velocity` 归一化 | 船头朝向（现状）、拖尾走向 |
| **加速度方向** | `fieldAcceleration` 求和 | 受力反馈（仅提示，不改变运动） |
| **朝向** | 目前 = 运动方向 | 同上 |

**不得**因为金球施加斥力，就凭空给飞船添加不符合实际运动的推进速度或引擎尾焰方向。视觉要帮玩家理解，不能误导玩家。

### 5.3 要做的表现

- **运动尾迹**：基于真实世界速度，长度随速度增长（详见 `gravity-field-vfx.md` 的拖尾一节）。
- **受力反馈**：低频、低振幅——例如船体沿加速度方向有 ≤ 0.6 px 的偏移，或加速度方向上一条 ≤ 0.35 alpha 的短拖影。**不要做屏幕震动**（明确不做）。
- **危险接近提示**：与 `collision: 'hazard'` / `'capture'` 天体距离低于 2.5 倍半径和时，在飞船周围出现 `HUD_WARN` 色调的呼吸环，周期 0.9 s。这是**屏幕空间** UI 语汇，画在 `ctx.restore()` 之后。
- **入港 / 停靠**：低速接近空间站时，飞船周围的推进感应该减弱而不是增强——停靠是"安静"的事件。
- **虫洞转场**：见 `celestial-effects.md`。

## 6. 场景视觉层级

### 6.1 世界空间的绘制顺序

`canvas.ts` 的 `render()` 里，世界变换之内，顺序必须是：

```
1. 星云（世界空间，视差最远层，加法）
2. 时空明暗褶皱（背景 source-over；与已绘制星空共享扰动采样）
3. 预测虚线
4. 尾迹（玩家 → 飞船）
5. 天体（drawBody）
6. 玩家节点（光晕 → 本体 → 标签）
7. 飞船
```

屏幕空间（`restore()` 之后）：合力箭头（仅 debug）→ 危险提示环 → 边缘箭头 → 小地图 → HUD 文字。

**理由**：明暗褶皱只影响背景，必须在预测线与实体之下；不能通过位移 / 染色危险轮廓表达空间变化。完整背景顺序与屏幕星点 / 世界印章的变换边界见 `gravity-field-vfx.md` §9.4，避免星云晚画把明暗覆盖掉。

### 6.2 三个档位的区别

| 模式 | 场范围怎么表达 | 线条/箭头 | 用途 |
| --- | --- | --- | --- |
| `?fx=off` | 旧版填充圆 + 描边（`LEGACY_*`） | 无 | **逐像素基线**，永远不动 |
| `?fx=low/medium/high` | **星空形变 + 明暗褶皱 + 交互扰动**，按质量门控；low 默认只保留节点 / 尾迹 | 无 | 正式画面 |
| `?dev=1`（DEV 构建） | 在所选 fx 档之上叠加：三圈等高线 + 合力箭头 | 有 | 开发调试 |

> **原作者历史记录（2026-10-16，不代表当前分支已包含全部实现）。** `field-visuals.ts` 的等高线环与合力箭头**已降级为 debug 专用**——这个决定是对的，两处都验证过：一是画面上环只会读成"几圈光晕"，二是 `nodeGlow` 那次契约破坏证明了正式档每加一层都得有 spec 门控。
>
> **Deprecated / Rejected Experiment**：原表曾推荐常驻吸引 / 排斥粒子，实际被玩家否决并删除，历史数据与 bug 留在 `gravity-field-vfx.md` §3–7。此结论针对本实验，不等于禁止连续氛围变化；新版按 `SKILL.md` §8 区分玩法反馈与视觉质感。上表中明暗褶皱 / 交互扰动是本次规范升级，尚未实装 / 试玩。
> 保留的例外：**`ready` / `paused` 下未激活玩家场的虚线范围环**（`drawPending`）属于"我站这儿能覆盖多远"的摆位 UI，**留在正式档**——它不是场线可视化，是操作提示。

## 7. HUD 风格

保持现状的整体结构（左上状态文字、右下小地图面板、边缘箭头），只做两点：

1. **不加辉光、不加渐变、不加装饰线**。HUD 是仪器，不是特效。
2. **维持主次**：HUD 文字 ≤ `TEXT` / `HUD_TEXT`，永远不与飞船、危险天体争夺最亮元素的位置。

必须保证：HUD 面板不遮挡飞船与关键障碍。左上角状态文字所在区域**不要**放暗角（vignette）——会压低文字对比度。**本 Skill 不做暗角。**

## 8. 动画节奏

所有时长用**视觉时钟** `VisualState.time`（`scene-visuals.ts`，已被 `MAX_FRAME_SECONDS = 0.1` 钳位），不使用帧计数。

| 效果 | 时长 / 周期 | 备注 |
| --- | --- | --- |
| 稳态空间起伏 | 约 23 / 37 s 两种慢变化，峰值明暗约 0.002 | 可选、低幅、不可读成周期呼吸圈 |
| 交互空间扰动 | attack 90 ms / decay 常数 0.85 s | 事件触发、末尾平滑归零，共享 H |
| 关闭恢复 | 时间常数约 0.35 s | 保留消退快照，不硬切 |
| 吸引粒子寿命（弃用实验） | 0.45 – 0.90 s | 每个粒子在范围内随机 |
| 排斥粒子寿命（弃用实验） | 0.60 – 1.30 s | 比吸引长，读出"喷散" |
| 粒子淡入 / 淡出 | 寿命的 15% / 35% | 两端都要有，不能硬切 |
| 危险接近呼吸 | 0.9 s 周期 | |
| 星空漂移 | 游戏内 0；标题页 8 px/s | 现状，保持 |
| 摄像机跟随 | `1 - exp(-5·dt)` | 现状 `camera.ts`，不要改 |

**节奏判断**：玩法信息与视觉氛围不同；允许安静的连续变化塑造空间，强烈动画优先响应真实状态变化。所有效果都要保持可读性并通过实际试玩，不能只以“相邻两帧有没有新信息”决定去留。

**冻结语义**（与 `updateVisuals` 的既有门控一致）：`phase !== 'running'` 时，空间事件、明暗起伏与尾迹**停止演化**；`ready` 时场粒子为空；`completed` / `failed` 后不再增长。唯一允许继续动的是**纯 UI 动画**（脉搏、呼吸）——并在文档里写清哪些属于这一类。

## 9. 美术禁忌

出现任何一条就算不合格：

- ❌ 全屏或大范围的高 alpha 填充盘（这正是之前"大圆套八边形"的成因之一）。
- ❌ 用规则圆环 / 虚线 / 同心圆**当作引力场的主要表达**。
- ❌ 教科书式引力线、磁场线、网格、梳状箭头出现在正式画面。
- ❌ 多个巨大的实心光环长期占据画面，或把几个缩放渐变盘当作时空织物。
- ❌ 持续汇聚 / 扩散的引力场粒子；静态蓝 / 金染色团作为唯一表达。
- ❌ 雷达扫描般的清晰波环、明显同心圆边界或与星点无关的循环明暗动画。
- ❌ 过度 bloom 让黑洞、陨石轮廓失去边缘。
- ❌ 粒子数量或尺寸大到遮蔽飞船与危险天体。
- ❌ 纯装饰性的随机闪光、逐帧重随机。
- ❌ 与真实运动不对应的视觉反馈（凭空推进、假加速度）。
- ❌ 节点用非身份色（蓝必须吸引、金必须排斥）。
- ❌ HUD 加辉光或装饰。
- ❌ 任何特效写入 `GameState` / `Camera` / `Trajectory`。
- ❌ 在曲线路径上断言逐位相等这类会 flaky 的测试（见 `performance-and-qa.md`）。

## 10. 跨场景的视觉统一

Level 0 教学 / Level 1 逃离太阳系 / Level 2 银河深渊 / Endless，四者的**视觉语法必须一致**，只换"主角天体"：

- 颜色 token 不分关卡——`ATTRACT` 永远是蓝、`REPEL` 永远是金。
- 亮度阶梯不分关卡。
- 粒子的尺寸范围、寿命、alpha 阶梯不分关卡。
- 变的只有：环境主光源（太阳的暖光、黑洞的冷暗）、星云配色权重、天体密度、危险色出现的频率。

新关卡需要新元素时，**先加到 `palette.ts` 并对齐亮度阶梯**，再写实现；不要就地发明颜色。
