# 天体特效 · 纯二维实现

所有天体都在 `src/render/celestial.ts` 的 `drawBody(ctx, body, camera)` 里，通过 `ctx.translate(body.position.x, body.position.y)` 后**围绕原点**绘制。

> **这个"围绕原点绘制"的约定不是风格，是正确性。** `CanvasGradient` 的坐标在**绘制时刻**的用户空间里解析，所以建在原点、按 `(kind, 量化半径)` 缓存的渐变可以被任何位置的天体复用（`RADIUS_STEP = 4`）。任何新天体都必须在原点画，否则缓存失效或串味。

---

## 0. 三条全局硬契约

1. **视觉不得超出碰撞半径而不加说明。** 碰撞用精确的 `body.radius`（`game.ts` 的 `sweptOverlap`）。画到半径外面的轮廓，等于让玩家在"看起来还没碰到"的地方被判定撞击。既有的 `ROCK_MAX = 1.0` 就是这条的代码化形式，并已有测试断言。
2. **危险区绝不被覆盖。** 黑洞的 `captureRadius ?? radius` 实心暗盘是危险区本身，**必须原样绘制、任何东西不得压在上面**（现有代码注释已明确）。
3. **天体位置必须是真实物理位置。** 行星被玩家引力推动时，视觉位置跟随 `body.position`，**不得用预设动画替代其运动状态**。

## 1. 太阳（`star`）

太阳巨大且明亮，**但绝不能让整个画面被白色光晕覆盖**。

### 1.1 盘面

复用既有渐变（`celestial.ts` 的 `star()`）：`createRadialGradient(0, 0, 0, 0, 0, 2.4 * r)`，stop 为 `STAR_CORE` → `STAR_MID`(0.35) → `STAR_FADE`(0.55) → `STAR_GLOW`(1，全透明)。

**新增约束（防白屏）**：光晕半径随缩放收缩。

```ts
const viewportDiag = Math.hypot(camera.width, camera.height);
const glowR = Math.min(2.4 * r, 0.55 * viewportDiag / camera.zoom);
```

当太阳近到光晕会吃掉半个屏幕时，光晕被钳住，中心依然明亮但不再淹没画面。

### 1.2 日冕

在盘面之外 `1.02r → 1.35r` 叠一圈**低 alpha** 的暖色渐变（峰值 ≤ 0.16），`lighter` 混合。**不加尖刺、不加油画丝状结构**——那是霓虹感，与本作气质相反。

### 1.3 表面纹理（缓慢变化）

用 3–5 个**确定性**的明暗斑点（由 `seededRandom(hashId(body.id))` 生成，位置与半径固定），随视觉时钟极慢地改变强度：

```
intensity_k = 0.5 + 0.5 * sin(2π * (t / 9.0) + phase_k)
```

周期 **9 s**，峰值 alpha 变化 ≤ 0.12，**不改变位置**。

> **不要**每帧重新生成噪声——那会变成闪烁的雪花。位置固定、只有亮度呼吸。

### 1.4 日珥粒子

每秒 3–6 个高亮粒子沿半径方向向上抛射，寿命 **1.2–2.4 s**，重力用**视觉近似**（一个固定的向下偏置即可），**不参与模拟**。

- 粒子从盘面边缘生成，速度方向在法线 ±35° 内随机。
- 颜色用 `STAR_MID` → `STAR_CORE` 的亮度桶。
- **明确**：这些是 VFX 粒子，不是 `Body`，不进 `game.bodies`，不产生引力、不参与碰撞。

### 1.5 危险提示

太阳的 `collision: 'hazard'`。当飞船距离 < 2.5 倍（太阳半径 + 飞船半径）时，飞船周围出现 `HUD_WARN` 色调的呼吸环（周期 0.9 s，屏幕空间）。这是**唯一**允许的暖色警告语汇，不要另外发明。

### 1.6 LOD

`screenRadius = r * camera.zoom`：

- `< 8 px`：只画 `STAR_CORE` 实心点，无渐变、无日珥、无纹理。
- `< 24 px`：渐变盘面 + 日冕，无纹理、无日珥。
- `≥ 24 px`：全量。

## 2. 行星与行星环（`planet`）

### 2.1 盘面（已实现，保持）

```ts
ctx.createRadialGradient(-0.34 * r, -0.44 * r, 0.06 * r, 0, 0, 1.02 * r);
// stops: PLANET_LIT → PLANET_BASE(0.45) → PLANET_DARK(1)
```

光源**固定在世界坐标左上**，所以同一个场景里所有行星受光一致——这是刻意的，不要改成"朝向太阳"。

大气辉光画在 `1.14r`，**先于**盘面绘制，因此只会在轮廓外侧露出。盘面**不描边**，保证碰撞边缘锐利。

### 2.2 行星环

`createRadialGradient` 做不出环（它在角度上均匀），必须用**椭圆环带**：

```ts
ctx.save();
ctx.rotate(tilt);                     // tilt 来自 seededRandom，固定
ctx.scale(1, 0.28);                   // 压扁成透视感
ctx.beginPath(); ctx.arc(0, 0, ringR, 0, Math.PI * 2);
ctx.restore();                        // 注意：路径在 restore 前建立，变换已烘焙进路径
// 用 lineWidth = ringWidth/zoom 的 stroke 得到"环带"而不是"圆盘"
```

前后分层（让环从行星后面绕过、再从前面穿过）：

1. 画**环的后半**（裁剪到椭圆上半）
2. 画行星盘面
3. 画**环的前半**（裁剪到下半）

### 2.3 环半径的硬约束

> **环的外半径必须 ≤ `body.radius`**，除非该关卡的碰撞半径被显式放大到覆盖环。

理由与 `ROCK_MAX = 1.0` 完全相同：行星的 `collision: 'hazard'` 用精确 `radius` 判定。一个画到 `2.2r` 的环会让玩家以为"环以内都是危险区"，而实际判定半径只有 `1r`——这属于**静默误导**。

两种合法做法，二选一：

- **A（推荐）**：环画在 `1.0r` 以内，视觉上是"贴着星球的一圈"。
- **B**：在关卡里把该行星的 `radius` 设为包含环的外径，并在视觉上让**碰撞边界可见**（例如环外缘用略亮的描边暗示边界）。做了 B 就必须在 README 里写明这是有意的玩法设计。

### 2.4 LOD

- `< 6 px`：单色圆点（`PLANET_BASE`）。
- `< 20 px`：盘面渐变，无大气、无环。
- `≥ 20 px`：全量（盘面 + 大气 + 环）。

## 3. 小行星（`asteroid`）

### 3.1 已实现，保持

`rockShape(id)` 用 `seededRandom(hashId(id))` 生成 `ROCK_VERTICES = 11` 个顶点的半径因子，**钳在 `[0.86, 1.0]`**。3 个坑，中心在 `0.55r` 内、宽度 ≤ `0.20r`，最深到 `0.75r`，安全落在 `0.86r` 最小轮廓之内。

**这两条数字不要动**：上限保证轮廓不越出碰撞半径，下限保证坑不咬穿轮廓。

### 3.2 可以增加的

- 一道**极淡**的高光弧（受光左上，与行星一致）：`0.86r` 处的一条约 70° 的圆弧，alpha ≤ 0.14。
- **不做**：旋转动画（小行星确实会自转，但那需要给 `Body` 加角速度——那是物理，不是视觉）。想要自转感，只能让表面纹理在**原地**缓慢变化，且必须确定性。

### 3.3 LOD

- `< 4 px`：`ROCK_BASE` 圆点，无轮廓变形。
- `< 12 px`：轮廓 + 填充，无坑、无高光。
- `≥ 12 px`：全量。

## 4. 黑洞（`black_hole`）

### 4.1 不可动的部分

```ts
disc(ctx, body.captureRadius ?? body.radius, VOID);   // 危险区本体，原样保留
```

**这一个圆盘不得被任何东西覆盖、缩小或改色。** 它是玩家判断生死的唯一依据。

### 4.2 已实现，保持

- `1.35r` 的光晕环带（`HOLE_HALO` → `HOLE_HALO_OUT`）
- `1.06r` 的光子环 `PHOTON_RING`（1.4/zoom）

### 4.3 新增：吸积盘

一个**扁椭圆**的环带，绕黑洞缓慢旋转：

- 外径 `2.0r – 2.6r`，内径从 `captureRadius` 起——**内侧绝不能侵入吞噬盘**。
- 压扁比 `0.22 – 0.30`（与水平面成视角）。
- 旋转：整体角速度约 **0.35 rad/s**（一圈约 18 s），用视觉时钟驱动。
- 色彩：由内到外 `#b79ae0` → `#6a4a9c` → 透明，整盘峰值 alpha ≤ 0.22，`lighter`。
- **控制遮挡**：吸积盘的 alpha 必须低于飞船与危险天体轮廓。飞船掠过时，盘面不得让飞船难以辨认。

### 4.4 新增：环绕粒子

- 常驻 **40–90** 个粒子（按质量档位），分布在 `1.05r – 2.4r` 的环形带内。
- 每个粒子沿**开普勒式**轨道运动：角速度 ∝ `1 / d^1.5`（内快外慢）——这是让盘面"活起来"的关键，匀速旋转一眼就假。
- 粒子为点状，尺寸 0.6–1.6 世界单位。
- **这些粒子不受玩家引力场影响**：黑洞附近由黑洞主导，且让它们响应玩家会让玩家误以为可以推动黑洞。
- 粒子**不得**侵入 `captureRadius`。

### 4.5 局域暗化

黑洞周围 `4r` 内叠一层**极淡的径向压暗**（`#060a14`，峰值 ≤ 0.18），让它在深空中比别处更"沉"。渐变到 0，无可见边。

### 4.6 危险反馈

同太阳：飞船进入 2.5 倍安全距离时出现 `HUD_WARN` 呼吸环。黑洞可以用略冷的 `#c9a0ff` 变体，但**必须**在 `palette.ts` 里定义成常量。

### 4.7 明确不做

**不做广义相对论引力透镜。** Canvas 2D 没有可行的实现，硬做会吃掉全部帧预算。`2.4r` 处的环带与暗化已经足以表达"光线在这里被弯折"的印象。

## 5. 虫洞（`wormhole`）

### 5.1 已实现，保持

`ring(body.radius, STATION, 3/zoom)` + `ring(0.62 * body.radius, WORMHOLE_INNER, 1.5/zoom)` + 标签。

### 5.2 新增表现

- **旋转能量环**：内环 `0.62r` 上叠 2–3 段不等长的弧，以 **1.1 rad/s** 反向旋转（相对外环），读出"转"的感觉。
- **汇聚粒子**：粒子从 `0.9r` 外围向 `0.2r` 汇聚并消失，速率 40/s，寿命 0.5–0.9 s。方向用**径向向内**即可（虫洞不是引力场，不适用 `fieldAcceleration`；但也不要把它伪装成引力——不给它 `emitsGravity`）。
- **多层光晕**：`1.0r / 1.25r / 1.6r` 三层渐变，峰值 alpha 0.16 / 0.09 / 0.04。

### 5.3 转场（硬约束）

虫洞转场由场景状态机驱动：任务触发器写入 `game.pendingScene`，`SceneController` 消费它。

> **VFX 只允许读 `game.pendingScene` 来播放画面，绝不允许写它、也绝不允许改场景状态机。**

正确的视觉行为：检测到 `pendingScene` 从 `undefined` 变为有值时，播一个 **0.35 s** 的收缩/白化过场（屏幕空间覆盖层，alpha 峰值 ≤ 0.55），然后立即交还控制权。**不要**阻塞、不要 delay、不要自己改 phase。

## 6. 空间站（`station`）

### 6.1 已实现，保持

`disc(STATION_FILL)` + `ring(STATION, 3/zoom)` + 标签「空间港 · 低速抵达」。

标签是回归可读性的必需元素（`tests/render-visuals.test.ts` 一类测试依赖它），**不要动文字、不要动位置**。

### 6.2 可以增加的

- 一圈**极慢**的自转刻度（6–8 个短弧，0.15 rad/s）——表示这是个运行中的设施，而不是一个圆。**不做**实心光环，**不旋转本体圆环**。
- 停靠反馈：飞船进入半径内且速度 ≤ `maxEntrySpeed` 时，本体环的 alpha 从 1.0 缓慢升到 1.0（不闪烁），并在外层叠一圈 ≤ 0.12 的 `STATION_SOFT` 呼吸。**不要**放彩带、不要放文字特效——停靠是安静的事件。

### 6.3 已知的 lineWidth 泄漏

`station` 与 `wormhole` 分支**故意**在 `drawBody` 之后留下 `3/zoom` 的 `lineWidth`（现有注释已记录，且它是被基线对比钉住的既有行为）。**不要顺手"修"它**——那会悄悄改变小地图面板的边框宽度，属于基线对比要抓的改动，不是要偷偷带进来的改动。

## 7. 星云与深空背景

### 7.1 绝对不要用实体承载

> **绝不用 `layer: 'background'` 的 `Body` 来承载星云或星空。**

那会污染物理热路径：720 步的预测里，每个背景点都要过 `capabilitiesInto` / `bodyGravityInto` / 加速度求和。`physics/world.ts` 刚做过的非分配优化会被直接乘上背景点数。

背景永远活在**渲染状态**里（`VisualState`），不进 `game.bodies`。

### 7.2 星云

- **世界空间**，分 2 层，视差 0.22 / 0.48。
- 由 `6–14` 个**椭圆形柔光团**组成，每团的中心、半径、旋转、色相权重都来自 `seededRandom(sectorSeed(...))`——**按星域区块确定性生成**，保证大世界与无限区块下可复现。
- 单团峰值 alpha ≤ **0.14**，`lighter` 混合，颜色用 `NEBULA_A` / `NEBULA_B` / `NEBULA_C`。
- **渐变必须缓存**，按 `(色相索引, 量化半径)` 作 key。
- **每帧不得重新随机。** 同一个区块每次经过必须长得一模一样。

对比度要求：星云是**气氛**，不是信息。它的最亮处必须**暗于**最暗的天体轮廓。如果玩家开始把星云误认为可交互天体，就是做错了。

### 7.3 区块化与无限世界

按世界坐标分块（例如 `1024 × 1024` 世界单位一块），只对**视野覆盖到的块**生成与绘制。块内容确定性地由 `(blockX, blockY, seed)` 决定。

- 缓存最近访问的 N 个块（`Map`，按 LRU 淘汰，**上限约 24 块**）。
- 离开视野的块可回收；回到同一块时**必须**得到相同内容。
- `state.levelId` 或 `scenes.revision` 变化时清空缓存。

### 7.4 程序化星空

**已经实现**（`src/render/starfield.ts`）：3 层视差 `0.14 / 0.34 / 0.68`，9 个亮度桶，每桶一次 `fill()`，与星数无关；tile 尺寸随视口推导，**不做取模回绕**，所以星空天然无限、永不突现。

**需要新增的只有一处**：`gravity-field-vfx.md` §9.1 的**引力场位移**——把每颗星在 `ctx.rect` 之前做一次径向位移，得到"星点向内压缩 / 向外推开"的印象。其余保持不动。

**仍然不做**：闪烁、暗角（vignette）。两者都违反"克制"取向，暗角还会压暗左上角 HUD 文字。

## 8. 大地图与摄像机适配

### 8.1 统一的世界变换

所有世界空间特效**必须**沿用 `canvas.ts` 的同一套变换，**不要**自己发明：

```ts
ctx.save();
ctx.translate(width / 2, height / 2);
ctx.scale(camera.zoom, camera.zoom);
ctx.translate(-camera.position.x, -camera.position.y);
// 世界空间
ctx.restore();
```

线宽一律 `n / camera.zoom`，这样屏幕上永远是 `n` 像素。

### 8.2 屏幕空间 vs 世界空间

| 属于屏幕空间 | 属于世界空间 |
| --- | --- |
| HUD、面板、边缘箭头 | 天体、粒子、尾迹、星云 |
| 合力箭头（debug） | 预测虚线 |
| 危险提示环 | 场范围虚线环 |
| 星空（**屏幕空间**，视差模拟深度） | 场明暗盘 |

**最典型的错误**是把 HUD 用世界坐标画，或者把粒子用屏幕坐标存。先问一句"这个元素应该跟着摄像机走吗"，再决定坐标空间。

### 8.3 设备像素比

DPR 由 `main.ts` 统一处理（`ctx.setTransform(dpr, 0, 0, dpr, 0, 0)`）。**特效层不得自己再乘一次 DPR**，也不要自己去读 `devicePixelRatio`。任何以"CSS 像素"为单位的常量（如星空 `layer.size`）都已经是屏幕空间单位，直接用。

### 8.4 裁剪

- 先用 `visibleEntities(camera, game.bodies)`（`src/render/visibility.ts`）或 `isVisible(camera, p, radius)` 做视口裁剪，再进 `switch`。
- **昂贵的天体**（黑洞吸积盘、日珥、星云团）在**大部分在屏幕外**时，可以降频更新（例如每 3 帧更新一次粒子状态）或直接跳过绘制——但**跨越边界时必须平滑**，不能在边缘突然出现。
- 屏幕外的实体**仍然被模拟**（这是既有设计：只有配置为 capture 的危险天体才会移除动态天体）。裁剪只影响绘制，**绝不影响模拟**。

### 8.5 缩放范围

`camera.zoom` 被 `setZoom` 钳在 **[0.3, 2]**。LOD 阈值都按 `r * camera.zoom`（屏幕像素半径）来判断，因此从 0.3 到 2 全程有效。缩放到最近时，行星 `r=65` 的屏幕半径是 130 px，此时才画满细节；最远时 19.5 px，只画渐变盘面。
