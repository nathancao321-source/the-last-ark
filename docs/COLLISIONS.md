# 二维天体接触系统

## 原因与接入边界

旧版 `stepGame` 只对飞船与危险体做扫掠失败检测，并移除进入黑洞的动态物体。`integrate` 对其他天体各自积分，没有普通天体对的检测、冲量或分离，所以两颗行星/小行星可以相互穿过。空间站原本也是允许超速穿过的目标区域。

现在由 `integrateContacts` 包装原有 kick–drift–kick 引力积分器，未改力场公式、加速度/速度上限或玩家能力。控制节点仍走独立模块，不进入实体接触列表。摄像机与可见性筛选不参与物理。

## 分层

- `physics/collision.ts`：相对运动圆扫掠，返回首次接触时间、法线、初始穿透深度。
- `physics/collision-detection.ts`：复用多尺度空间哈希，用两个实体的扫掠 AABB 筛候选，按时间寻找最早有效接触。
- `physics/collision-policy.ts`：实体能力、类型和关卡入港约束决定策略。
- `physics/collision-resolution.ts`：仅处理有冲量的接触与位置分离。
- `game/collision-events.ts`：吸收、摧毁、合并、失败和提示，不再叠加弹性反弹。
- `physics/contact-world.ts`：引力子步、首次接触推进、事件处理、剩余时间重新扫掠。
- `game/mission.ts`：空间站速度阈值和前置目标共享给接触层；入港成功仍由任务系统判定。

## 策略表

| 接触组合 | 默认结果 |
| --- | --- |
| 小行星 / 小行星 | 无摩擦二维冲量，默认恢复系数 0.45，质量加权分离 |
| 小行星 / 行星、恒星 | 移除小行星；不把其动量硬加给巨大天体 |
| 行星、恒星之间 | 摧毁质量较小者；同质量按稳定实体顺序保留前者 |
| 飞船 / 小行星、行星、恒星 | 首次接触失败；保留接触时速度，冻结已失败状态，不重复触发 |
| 飞船 / 空间站 | 满足入港速度及任务前置条件才可进入；超速在圆形外缘接触，默认恢复系数 0.35，显示 TOO FAST TO DOCK |
| 飞船 / 虫洞 | 非实体目标；仍由任务扫掠触发转场，不产生冲量 |
| 普通物体 / 黑洞事件视界 | 被吸收并移除；飞船失败，不在视界表面弹回 |
| 背景、隐藏、加载保护中的实体 | 不参与接触 |
| 两个玩家投影 | 不参与任何实体碰撞；既有黑洞捕获/喷出机制独立保留 |

实体圆半径就是 `Body.radius`，不包含日冕、发光、行星环。事件视界使用 `captureRadius`。空间站圆环是停靠区域：低速允许进入，随后按关卡 `fullContainment` 等条件判定，绝不吸附或直接清零船速。高速弹开后没有永久锁定，可以正常施力后重新靠近。虫洞类星际转移区仍不反弹。

`Body.contact` 可配置 `mass`、`restitution`、`largeBody: 'destroy' | 'merge' | 'fail'`、无任务阈值时的 `dockingSpeed`。质量默认 `radius³ × density`，沿用现有天体体积尺度；运动/碰撞依然是二维，不是三维刚体模拟。恢复系数限制在 [0,1]，两个小行星取较小值。空间站优先使用任务的阈值，默认备用 48。

选择 merge 时，保留较大质量实体，按质量合成质心/动量、按体积合成半径，移除另一个；合并物解除原轨道脚本和位移约束，改为自由动态体。静态主实体则保持固定位置。默认摧毁不生成碎片、不增加巨体质量，属于明确的游戏化吸收，不声称严格守恒。

## 求解与连续性

对圆心相对位置 p、相对位移 v，求 `|p + t·v|² = (rA+rB)²` 的最小 t∈[0,1]。两个物体都在移动时也适用。初始重叠立即处理；完全同心用相对运动或固定轴确定法线，避免除零。

只在相对法向速度 vn<0 时施加 `j = -(1+e)·vn / (invMassA+invMassB)`。静态、运动学及带解析轨道基线的实体逆质量为0，普通冲量不会与轨道脚本争夺控制权。静态实体的预置 velocity 不当成真实接触速度。穿透按逆质量比例修正，加 1e-5 世界单位间隙，避免重复零时间碰撞。现有全局速度上限继续生效。

碰撞后的动量作为新的惯性基线，清除受撞动态体旧的 `stabilizationState.playerVelocity` 分解，防止选择性阻尼重新注入碰撞前速度；不清零实际速度，不给飞船加自动阻尼。后续玩家施力仍正常进入扰动分解。

每个固定步先按曲率误差估计 `a·dt²/8` 选 1–16 个子步；a 包含原加速度上限170和解析轨道 `r·ω²`。容差为最小碰撞半径的5%（半径用于计算时最多8，容差下限0.01）。每段仍复用原引力积分。接触后把路径推进到首次接触点，再以新速度计算剩余行程并重新扫掠，处理同一步内的二次碰撞。航程累加这些真实移动段，位置纠偏不算飞行距离。

单子步最多求解32次接触，达到预算就保守停在最后接触位置、保留速度供下一物理步继续，不越过尚未解开的物体。DEV 显示预算耗尽提示。每步最多记录64条简要事件，逐步覆盖，不累积无界日志。

## 数量与性能

主线只有少量天体；无限模式已有活跃上限325（54个区块，每块最多6体加方舟）。接触沿用多尺度空间哈希，不遍历全宇宙两两组合，也不依赖屏幕范围。已加载但屏幕外的天体照常发生碰撞。卸载区块仍遵守有限缓存/冻结近似，不新增远场全宇宙模拟。

## 验证及复现

`tests/collisions.test.ts` 覆盖正碰、斜碰、不同质量、深度重叠/同心、静态与运动学、连续碰撞能量、巨体吸收、行星摧毁/合并/失败、轨道与接触共存、双方高速交叉、太阳实体半径、低/高速入港、任务前置条件、虫洞、事件视界、节点隔离、镜头无关、暂停/重试/预测、反弹航程和曲线扫掠。曲线测试专门构造整步直线弦会漏掉、子步能够捕获的接触。

仅开发模式提供这些独立配置，按 Space 启动：

- `?dev=1&scene=coop_test&section=collision-bounce`：两颗半径20的小行星以±100接近，接触后速度∓45。
- `?dev=1&scene=coop_test&section=collision-ccd`：半径0.5的船以240运动，撞到2.2单位外同半径小行星；单帧末位置判定会漏掉，实际停在x=551.20并失败。
- `?dev=1&scene=coop_test&section=collision-dock`：240船速撞站，反向84退开。
- `?dev=1&scene=coop_test&section=collision-dock-slow`：30船速正常进入，1.33秒完成。

这些隔离夹具关闭天体互引，以单独验证接触，正式关卡引力保留。浏览器实际检查以上四种情况及 R/暂停，未记录警告或错误。原试玩30条、合作6条、Moving World 9条及完整序章已重新验证；原太阳系、黑洞、无限探索路径继续通过。旧入港脚本改为提前部署金场并利用真实预测择机制动，不再依赖穿站。

## 仍有边界

- 不是通用工业刚体引擎：没有自转、摩擦、角动量、碎片生成或精确长期多体接触岛求解。
- 极密堆积、极大 dt 或极端解析轨道曲率会达到子步/接触预算；此时采用保守停留，不保证一次步进完全消除所有穿透。
- 力在短子步上计算，碰撞后的剩余段采用线性运动，不是解析积分弯曲受力路径；子步上限外不承诺任意尺度的严格 CCD。
- 任务触发器仍使用固定步起止位置的扫掠；同一步发生多次反弹并穿越多个传送器时的逐事件转场优先级尚未细分。现有静态虫洞/空间站任务和危险优先判定均有回归测试。
- 无限模式缓存淘汰后按种子重建，久远区块中被摧毁的物体可能重现；永久宇宙改动持久化不在本次范围。
