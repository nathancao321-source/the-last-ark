# THE LAST ARK：世界与连续场景设计

本文件是完整游戏路线与架构契约。当前普通入口提供 **完整 Level 0：First Contact → The Moving World**、**Level 1：Solar Exodus**、**Level 2：Beyond the Horizon**、银河边缘休整与原试玩；开发模式另有合作测试。Endless 仍为后续规划。

## 游戏定位与共同规则

人类最后的移民方舟寻找新家园。两名高等文明观察者通过高维引力场控制中心投影协助人类，不能直接驾驶方舟，只能改变周围天体的引力与斥力。游戏逐步从局部合作解谜走向大世界探索，保持双人同屏、二维世界，支持独立选择键盘、鼠标与标准 Xbox 手柄。

P1 使用 WASD / F 切换吸引，P2 使用方向键 / Enter 切换排斥。力场作用于所有配置为可受力的天体，不局限于飞船。大行星可缓慢推拉；太阳也可微弱推动；黑洞通过静态配置固定。飞船靠惯性、引力辅助和玩家配合航行，限速、危险碰撞、低速入港继续有效。

暂停允许部署玩家和观察预测。画面边缘不是物理边界，镜头自动拉远以同时容纳玩家与飞船；任务若需要限制范围，必须明确配置独立世界区域。

## 世界坐标与摄像机契约

- 每个实体 position / velocity 使用世界单位。Level.width / height 仅保留旧关卡参考尺寸，mapBounds 是导航参考范围；两者均不限制运动。
- missionBounds 可选，只有显式存在时才限制方舟。当前试玩未配置该边界。
- Camera 包含世界中心、缩放、视口 CSS 像素宽高。世界转屏幕：`screen = (world - camera.position) * zoom + viewport / 2`，逆变换对称。
- followGroup 根据方舟和两节点的位置、0.4秒速度前瞻构图。默认近景上限0.8，可调至2；自动拉远没有固定缩放下限。最终视野约束保证三个参与者均可见。缩放/尺寸不改变既有天体物理、任务或区块需求。
- Canvas 按 ResizeObserver 更新视口和 DPR；渲染时应用世界矩阵，HUD、小地图、边缘箭头在屏幕空间绘制。
- 玩家离屏有 P1 / P2 箭头和距方舟的距离；目标离屏有绿色方向提示。小地图显示当前已加载实体、任务目标与镜头范围，允许负坐标和远处对象。
- 当前不限制两玩家与方舟的距离，没有自动传送。已撤回地标导演、死区和弹簧速度缓冲；恢复三人速度前瞻包围盒中心的指数平滑跟随（系数4），拉远系数7、拉近1.5。没有地标切换，也没有终点死区框。

## 分层场景状态机

SceneId：title、prototype、tutorial_part_1、tutorial_part_2、solar_system、black_hole、endless。

GamePhase：ready、running、paused、failed、completed。例如 solar_system + paused 表示暂停太阳系任务，不是离开太阳系。

```text
title --章节选择--> tutorial_part_1 / prototype + ready
tutorial_part_1 + ready --Space--> 第一个操作提示（仍准备）--Space--> running
prototype + ready --Space--> running
running --Space / 失焦--> paused --Space--> running
running --危险规则--> failed
running --目标完成 / complete 动作--> completed
failed / completed / 运行中 --Shift+R--> 当前检查点 + ready
任意游戏阶段 --R--> 当前关卡初始配置 + ready
任意游戏场景 --Esc--> title
运行中 --配置的世界触发条件 + transition--> 已实现目标场景 + ready
```

SceneController 持有场景与 GameState；场景注册表决定可用性及 Level 配置。available 表示已实现可运行场景，planned 不可进入。Level0 两部分及 Solar Exodus 均 available，虫洞按任务显式转场；原试玩仍只显示胜利，不自动跳关。

切场景会创建独立状态，清空运行时目标与触发器记录，重置键盘、固定时钟和预测缓存，并将镜头定位到新出生点。单次触发器按 ID 去重；计划场景转场被拒绝且显示提示。当前所有转场规则只基于世界实体/区域/任务完成条件，不读取屏幕位置。

## 统一实体与能力配置

Entity 提供 id / kind / position / radius / layer；Body 增加速度和物理能力；Player 保留控制动力学配置及力场，与输入设备无关。玩家是统一实体类型的一员，但不进入天体积分列表。

| 类型 | 默认运动 | 发出引力 | 默认碰撞 | 力场响应 |
| --- | --- | --- | --- | --- |
| ship | dynamic | 是 | 自身为受检主体 | 1 |
| player | 独立控制动力学 | 否 | 无 | 0 |
| asteroid | dynamic | 是 | hazard | 1 |
| planet | dynamic | 是 | hazard | 0.18 |
| star | dynamic | 是 | hazard | 0.02 |
| black_hole | static | 是 | capture | 0 |
| station | static | 否 | 无 | 0 |
| wormhole | static | 否 | 无 | 0 |

- 默认值集中在 game/entities.ts。可用 motion、emitsGravity、collision、affectedByFields、response、density、gravityRadius、maxSpeed、captureRadius 覆盖。
- static 无论预设速度或受力参数为何都不移动，仍可作为引力源。kinematic 按预设速度运动，不接受加速度，适用于未来按轨迹移动的源。
- background 层强制静止、不施力、不碰撞，仅供渲染。hidden 只隐藏视觉，不取消物理。
- 触发实体由任务按 ID 引用；虫洞、空间站不需要实体碰撞才能触发。原试玩空间港已转为 station，使用 near_entity + maxSpeed + fullContainment 判断抵达。
- 半径和密度确定球体质量与引力。response 是游戏化加速度系数，不是严格真实天体动力学；它让大天体缓慢运动，不锁死行星。固定黑洞与可移动恒星由能力配置实现，积分器不检查特定天体名称。
- 兼容旧 Level.port：没有 mission 时自动转换为低速区域目标。新关卡应优先使用实体目标，避免显示位置与触发区域分离。

## 任务目标、触发器与检查点

Mission 分离 objectives 与 triggers。Objective 包含完成条件、可选前置目标、可选任务标记、导航目标；完成记录保存在 MissionState。必需目标全部完成时默认胜利，可用 completeOnObjectives=false 改成纯触发驱动。

已实现条件：

| 条件 | 用途 |
| --- | --- |
| enter_region | 从外部进入圆形或矩形区域；扫掠检测防止高速跳过 |
| inside_region | 当前实体在区域内 |
| speed_in_region | 当前完整/中心入区且速度不超过阈值 |
| entity_at | 指定天体被移到指定区域 |
| cross_band | 穿过圆形轨道带，含两个端点都在外部的情况 |
| near_entity | 接触/进入目标实体范围，支持移动目标、可选低速完整入港 |
| objective_complete / all | 阶段完成或多个条件同时满足 |

区域类型为 circle、rect、band。enter_region 在已经位于区域内时不会再次触发，inside_region 可以；低速条件必须在当前物理步结束时处于目标内，不能用高速扫过算完成。任务目标一旦完成便保持完成，适合阶段任务；若需要同时满足多个条件，应使用 all。

触发器动作：hint、checkpoint、transition、complete。每个触发器仅执行一次，前置目标可限制触发顺序。危险规则优先于目标完成。

检查点保存天体位置/速度、玩家、任务完成记录、触发记录、计时和关卡配置，不包含旧检查点的递归副本。恢复后暂停在 ready 并关闭力场，留给玩家调整；R 丢弃阶段进度并从头开始。当前为内存检查点，刷新页面不会保存。

原试玩的配置示例：方舟从外部进入世界矩形 x=640–700、y=100–280 时保存 after-bypass 检查点并给出制动提示。它不改变物理轨迹，不阻止从其他路线通关。First Contact 已通过 near_entity + transition 使用真实虫洞转场，教学提示另由下述 TutorialConfig 控制。

## 物理、预测与性能

1. FixedClock 以 1/60 秒执行逻辑，与渲染帧率、镜头、DPR 解耦。每帧最多补算 15 步；慢设备可能丢弃超额实时时间，不增加单步长度。
2. Velocity Verlet 对同一步的全部已加载动态天体使用共同位置快照。先半步加速，再推进，再重算源位置并半步加速。保留软化距离、有限力场半径、单源/合加速度上限与速度上限。
3. 移动引力源自然形成引力弹弓，无额外“弹弓奖励”。固定源只弯曲轨迹；当前力场截断与硬限速是游戏化取舍。
4. 多分辨率 SpatialIndex 按引力影响 AABB 索引源；动态实体查询其位置附近的候选源，再用实际半径公式过滤。不是全宇宙两两计算。超大影响域使用较大格子。拥挤局部仍可能较昂贵，不承诺无限规模恒定时间。
5. 危险实体用扫掠 AABB 做碰撞候选查询，然后相对扫掠圆精确判定。离屏不移除陨石；捕获危险仍能吞噬动态天体。
6. 渲染对已加载实体做视野相交裁剪，仅绘制可见实际实体。小地图绘制的是导航点。显示裁剪绝不暂停物理。
7. 预测用独立状态副本调用同一 stepGame，包含移动引力源、任务、速度限制、碰撞；包含已出生来袭体，但不预言依赖未来视野的生成事件。最多 12 秒，每秒更新 10 次；假定松开移动键、保持技能开关（包含节点辅助制动），遇到失败、完成或转场停止。没有 Worker 或大规模预测预算系统。

## 星域扩展接口（未连接加载器）

world/sectors.ts 定义 SectorKey、SectorData 和 SectorProvider.load / save / unload。区块边长 2048，负坐标采用 floor。worldSeed + 区块整数坐标生成确定种子，seededRandom 不依赖 Math.random 或加载顺序。

planSectors 将方舟与两位玩家作为需求焦点，默认规划至多 27 个相邻区块；镜头/缩放不是需求输入。接口已通过确定性测试，但原试玩把全部4个天体留在内存，Solar Exodus 初始15个、来袭后17个，没有程序化生成、磁盘保存、异步加载调度或区块卸载逻辑。

未来实现约束：

- 卸载前保存动态状态，再次加载优先恢复，不可仅凭种子让移动过的天体回到初始位置。
- 区块加载需按引力/碰撞作用半径保留邻域和跨区源，不能只加载屏幕可见区；应给生成器配置最大作用半径，并纳入需求规划。
- 玩家分散时的加载上限、远场近似和未加载动态实体如何推进，需要单独设计与验证。当前 planSectors 是基础空间需求接口，不是完整物理正确的流式调度器。
- 加入生成器版本和存档版本，再保证跨版本复现。当前只保证同种子、同算法、同配置下序列可复现。
- 场景转场边界未来可放异步加载过渡；当前只支持同步已注册配置，不假装加载未来星域。

## 控制节点与运动稳定机制（2026-10-15 追加）

### 世界观与物理边界

蓝色/金色节点是两个高维文明在三维宇宙中的**引力场控制中心投影**。它们不是物理星球，没有普通天体的重力响应或反作用运动。Player 的速度只由 physics/player.ts 的控制动力学更新；physics/world.ts 永远不更新玩家。

真实天体保留原有软化牛顿式引力、惯性、移动源弹弓、限速和碰撞。玩家场可以做正功、负功或捕获方舟进入束缚轨道，绝不因“合作平衡”而禁止。场的位置可以在启用技能时自由改变，技能仍为 F/Enter 点按开关。

### 节点控制动力学

两节点配置相同：speed=260、acceleration=650、braking=433.333…。每步 targetVelocity 为归一化输入乘 speed；把 targetVelocity-currentVelocity 限制到 acceleration×dt，再累加速度并更新位置。松键采用 braking，不赋值为零；最后一小步在剩余速度差不超过允许变化时自然停稳。

结果约 0.4 秒达到常规最高速、0.6 秒松键停下，反向约 0.8 秒从 +260 转到 -260。满速松键滑行约76单位，是待真人试玩的重要手感参数。260 的节点速度可赶上巡航65、最高240的方舟，不需要作弊传送。暂停允许节点运动，天体和计时冻结；失败/完成冻结整个模拟。重试/切场景恢复相应玩家位置、速度和开关策略，不绕过输入模块进行普通移动。

### 非飞船天体的选择性稳定

Body.stabilization 为可选配置，状态为 stabilizationState.playerVelocity 与 idleTime。每次半步积分把自然引力与玩家加速度分开，保留合加速度限幅比例，并将玩家冲量累加到 v_player；v_base=v_total-v_player。因此基础初速度（含公转初速度）及环境引力贡献不被阻尼。

任一玩家单独贡献的响应后加速度超过 fieldEpsilon 时，不施加额外阻尼；两个相互抵消的场也不启用阻尼。仅仅按着技能但物体在范围外不算有效施力。离场后：

```text
ramp(t) = 1 - exp(-t / rampSeconds)
v_player *= exp(-ln(2) / halfLife * integral(ramp(t), t0, t1))
v_total = v_base + v_player
```

使用 ramp 的解析积分，使半衰期与物理步长正确结合；默认 rampSeconds=0.25、sleepSpeed=0.03、fieldEpsilon=0.0001。小于 sleepSpeed 只清掉玩家扰动，不能连公转/环境运动一起清零。没有出生点弹簧、不回原位。再入有效力场立即接受正常施力，并重置 idleTime。船体能力禁止稳定，即使误填配置也忽略；黑洞 static 保持不动。

原试玩 planet 半衰期1.2秒，asteroid为1秒；开发测试三颗陨石依次1/1.1/0.9秒。对有预设物理轨道的天体，只衰减玩家速度分量，不衰减初始切向速度和中心天体引力。**该分解是游戏近似，不是严格的轨道扰动理论**：实际位置变了会改变自然引力，因此减速后可能处于另一条轨道，不保证返回原轨道。极强环境引力仍可让天体离开区域；不能为保留谜题对象偷偷取消它。初始自由漂移同样保留。

限速可能按比例缩放基础与扰动分量，触及速度上限仍非能量守恒。关闭稳定机制只关闭额外衰减，不关闭原有软化、响应系数或硬限速。

配置由每个实体承担，世界积分器不根据 planet/asteroid 的具体 ID 决定行为。默认类型能力集中在 entities.ts；当前 Solar Orbiting Planet 使用解析公转基线与独立玩家扰动，Tutorial Planet 使用低响应及稳定参数，不需要新增带特殊规则的名称类型。

### 效率评价

GameState.distance 累计方舟每个有效物理步的位置差长度，elapsed 是实际模拟时长。completed 显示完成时间、实际航程，以及可选星级。原试玩与合作测试的 Level.scoring 为18秒三星、30秒二星、其余一星。**无时间导致失败的代码**，慢速完成始终合法。

暂停部署时间不计入；恢复检查点还原对应的时间/航程，失败尝试不会累计到最终成绩。当前不是防作弊排行榜。探索模式使用 mode='exploration'，即使误填 scoring 也不产生限时星级。

### 开发合作场景

新增 coop_test 只在 Vite DEV 且 dev=1 时注册为 available；普通/生产入口仍不开放。它是专门验证合作的测试场景，不推进 Level0/太阳系剧情。三颗移动陨石 的全体天体能力与普通关卡一致，没有任一玩家必须按键的条件，也没有“只有 P2 能触发”的机关。

几何意图：P2 从第一颗陨石上侧排斥清路时，也会减速/偏转附近飞船；P1 可修正航线，稍后再转向目标。重新部署 P1 时也会牵引附近陨石，两个玩家必须考虑干扰。目标仅为 ship 完整且低速进入 station。复现步骤、6组自动路线、浏览器通关数据见 README。没有进行单人/双人的受控对照实验，因此不能断言合作一定更快。

### 调试与预测契约

DEV URL 可独立改 halfLife.<entity-id>、moveSpeed、moveAcceleration、moveBraking，或 stabilization=off。参数解析后写入关卡副本，预测/重试共用，不修改公共配置或生产构建。运动调试数据显示节点位置/速度、场源强度与对方舟的瞬时加速度、方舟速度、时间、航程及扰动速度。

轨迹预测假设松开移动键并保留场开关，因此已有节点惯性会按照辅助制动继续运动。预测仍调用相同 stepGame，包含选择性稳定、关卡任务、碰撞与检查点状态；不修改真实数据。没有因效率评分或合作测试改变引力函数、加入轨道捕获禁令、重做视觉/黑洞/无限模式。

## 输入设备与玩家意图契约

输入流为 `设备适配器 → PlayerInputSource → PlayerInputs → Controls.players → applyPlayerIntent`。输入层仅表达意图，不引用 GameState 或 Player；物理层统一改变速度、位置与力场开关，天体引力积分不依赖设备类型。

`PlayerControlIntent` 为只读快照：

| 字段 | 契约 |
| --- | --- |
| moveX / moveY | 世界坐标轴控制量，各轴 −1…1；保留模拟量幅度，二维长度由物理层限制为 1 |
| abilityActive | 当前期望技能状态，而非本帧是否按下；键盘适配器负责 F/Enter 边沿切换并过滤重复事件 |
| targetWorldPosition? | 可选已采样世界目标；非零方向轴优先，否则进入目标追踪。没有目标且轴为零时辅助制动 |

每个玩家独立指定一个 source。键盘提供两个独立通道，Xbox 适配器提供摇杆和按钮意图，鼠标适配器按最新需求持续重投影屏幕指针得到世界目标。相同有状态通道不可同时分配两名玩家；同一键盘设备的两套按键是不同通道。换源清除该玩家新旧意图而不重置物理速度，另一玩家不受影响。固定步读取意图，渲染不负责推动玩家。输入快照复制坐标，过滤 NaN/Infinity，避免设备复用缓冲区污染已经读取的意图。

生命周期：releaseMovement 在失焦时清除方向/目标、保留显式技能开关；reset 在重试、转场、解绑/断连时清空所有意图。main 对所有已分配来源执行统一清理，键盘的全局 Space/R/Esc/缩放动作仍单独处理。Gamepad 断连检测和鼠标事件监听由各自适配器实现，不进入物理核心。

### 世界目标与跟随摄像机

`WorldTarget` 是不绑定 DOM 的坐标采样工具。MouseInput 保存最后的 client 指针位置，每个固定步依据最新 Canvas CSS 矩形与 Camera 重新 capture，输出当步世界点。DPR 不参与坐标计算。此处按最新用户选择改为持续屏幕追踪，替代先前“只在鼠标事件时锁定世界点”的约束；旧采样工具本身仍保持纯坐标转换。右键切换制动，制动时不输出目标，既有节点动力学负责平滑停下，再点右键恢复。移动指针/松开右键不解除制动；重试、换源、失焦清理指针状态。

目标模式仍走节点控制动力学。期望速度方向指向目标，大小取最高速度、制动距离速度 `sqrt(2×min(acceleration,braking)×distance)`、近目标速度 `distance/targetArrivalSeconds` 三者的较小值；近目标时间默认0.25秒，至少为单步 dt。减速使用 braking，其余使用 acceleration，每步速度变化仍受限，然后用新速度更新位置。目标突变、经过目标或清除目标都不会瞬移或瞬间停下；此辅助追踪仅用于非物理控制投影，不改变真实天体规则。

### 实际设备接入

已接入键盘、真实鼠标事件及 navigator.getGamepads()，由设备选择界面为每名玩家独立指定输入。共享鼠标或同一个手柄槽不能分给两人；换源只重置新旧意图，不清零物理速度。键盘+键盘、键盘+Xbox、鼠标+Xbox、鼠标+键盘、两个手柄均可配置。

鼠标在地图上开始追踪后接受窗口中的 mouse 指针移动，允许向地图外探索。左键切换技能，右键切换制动；屏幕鼠标持续投影为世界目标，由有限加速度追踪。打开全局星图暂停并释放鼠标目标，星图操作不会触发技能。

Xbox 接收 standard 映射，左摇杆径向回中死区0.25，启动阈值0.30（滞回防漂移），并连续重映射幅度，A切换技能，Menu确认教学/暂停。API不可用、未连接、非标准映射均显示状态并输出中性输入；断连关闭技能。重连、换源和失焦恢复要求摇杆/按钮回中立再接受输入，避免旧按钮造成误触。状态由每个适配器独立保存，另一玩家不受影响。真实硬件/驱动兼容性仍须实机验证，模拟报文测试不能代替该验收。

设置界面、页脚与教学按键文字随设备更新。保留键盘 R / Shift+R / Esc / 缩放；未实现重映射、震动或手柄控制整个HTML章节菜单。预测仍采用释放移动意图、保持技能状态的约定，不持续追踪鼠标目标。

## Level 0 第一部分：First Contact

### 场景与物理

first-contact.ts 是独立配置，只有船体 ark 和静止、无引力、无碰撞的 wormhole。方舟初始 (120,360)，速度 (45,0)；P1 初始 (260,230)，P2 初始 (80,460)。两节点沿用原有移动/力场参数，不能直接操纵方舟。虫洞中心 (760,80)，半径150，复用 near_entity 扫掠检测，船中心进入即触发，不限制速度。虫洞是否可进入与教学完成记录无关，提前抵达同样合法。

### 教学状态

Level.tutorial 保存预设步骤和阈值；GameState.tutorial 保存当前步、可读停留时长、有效施力观察时长、两玩家实际移动距离和已访问步骤。配置与运行状态分开。game/tutorial.ts 只读实体运动结果并更新教学状态/暂停标志，不写物理实体。每次进入新步骤返回检查点 ID，由 game.ts 统一保存完整状态。

| 顺序 | 提示主题 | 推进条件 |

## Solar Exodus 实施契约（2026-10-16）

### 主线与目标

`levels/solar-system.ts` 独立配置所有天体、外观、轨道、危害与阶段。地球附近出发 → 太阳危险绕行 → 内行星 → 小行星带 → 外行星 → 唯一终点：星际转移(5480,0), r=110，进入速度≤60。初始冥王星(4350,-120)，终点在其初始位置更右侧，至少200单位净间隔；不会把冥王星包在终点里。目标不随玩家推走的行星移动，允许玩家自由改变局面。

阶段以宽广世界半平面/实际出口区域触发，危险优先；没有强制狭窄航线或离屏失败。通过主要轨道段保存当前真实世界检查点。开发 section=earth/sun/belt/pluto 是不同初始配置，普通通关不调用任何传送或速度奖励。

### 真实积分与有限范围相互引力

太阳系不再配置 Orbit 解析驱动。创建时，用实际太阳场（同样的软化和范围衰减）计算 `v=sqrt(|a_sun|×r)` 并沿切向设置初速度；之后只有原有 Velocity Verlet 积分推进位置/速度。没有隐藏轨道加速度、自动回位或轨道捕获禁令。

太阳、九颗行星、物理小行星和飞船都是引力源，也接收附近源的引力。来源按作用范围 AABB 放入空间索引，再查询局部候选；不对未加载宇宙做两两计算。行星对船/陨石引力范围 max(360,radius×8)，同组行星间中心距离上限300，密度系数3；太阳引力范围6000。有限范围、软化和硬限速仍是游戏近似；不同源的截断半径可以不同，不保证截断边缘的严格动量守恒。

`affectedByFields` 只控制玩家技能，`receivesGravity` 单独控制环境引力；前者关闭不再错误地跳过后者。新增 `gravityResponse` 分离环境响应与玩家响应：太阳系动态天体为1，木星 response≈0.00058、土星≈0.00102、太阳 response=0.0001 只让玩家推动更难，不削弱自然引力。旧关卡未指定 gravityResponse 时保持原 response 约定，以保留既有路线。

玩家输入扰动仍单独记录并按半衰期衰减；自然引力与初始速度不自动阻尼。行星无距离上限。太阳保留先前指定的最大偏移配置，不宣称严格无约束N体系统。预设 Orbit 接口留在引擎兼容层，太阳系不再使用。背景碎石、目标区和控制节点不参加相互引力。

### 恒星交互

`game/stellar.ts` 根据 StellarConfig 判定，不按具体名称写物理特例。太阳半径100、引力范围6000、热区340；方舟HP100，热伤害线性增至80/s，核心碰撞立即失败。节点只要在恒星内持续3模拟秒就触发，无需技能开启；离开重置、暂停冻结、两节点同时进入则抵消计时。

金节点：恒星消失、引力/碰撞关闭，爆炸直接读取 burnRadius=340，与热区同一数据源；范围内飞船失败，其他实体不受爆炸冲量。蓝节点：半径32、强度×1.7、响应0.35、无灼烧中子星。太阳响应降至0.0001、半衰期0.9s、最大偏移60；中子星最大偏移320。**该范围约束仅用于先前明确要求稳定的恒星，不用于普通行星**，通过 displacementLimit 配置。约束只截去超界位移和向外速度，不把它拉回出生点。

### 视野感知的来袭生成

100个背景点不参加物理；3颗实际带区小行星加一次2颗来袭波。`world/encounters.ts` 接收最终渲染视野，整颗来袭体出生在右边界以外，额外空隙=max(180,视野宽×0.15)，朝出生时飞船方向以55单位/s前进。种子确定形状和偏移；同种子、同视野可复现。场景暂停/星图打开时不生成，同波仅一次，记录随检查点保存。未来波次可以配置在其他区域。

生成在主循环镜头跟随/最终适配完成后、绘图前发生，以保证当前屏幕内不突现；下一固定步加入普通积分及扫掠碰撞。没有完整天体两两计算或无限刷怪。视野只决定新实体出生位置，不能影响已存在实体的位置、速度、引力或任务规则。纯 stepGame 和预测不创建依赖视野的未来事件；自动完整路线测试显式运行相同相机/生成流程。超远取景下出生距离自然更远，不为了追上玩家而偷偷传送。

### 行星可操作性与重开修正

太阳系行星配置 `gravityPeer={group:'solar-planets',radius:300}`。`bodyGravity(source,target)` 对同组实体取双方peer半径和源半径的最小值，使用原平滑截止公式；空间索引仍按源最大影响范围查询。超过300中心距离双方不再互吸，不改变太阳对行星的向心引力，也不改变行星对飞船的原范围。分组是配置，不在积分器按天体名称分支。

太阳系行星的节点响应采用 `min(0.0125,0.005*(40/radius)^3)`。小型岩石和旧教学关响应保持原值；太阳响应0.0001，中子星0.35。自然引力响应仍为1，初始轨道与真实受力积分保留。太阳系压缩尺度下，这是可操作性近似，不能据此声称严格天体物理；长期持续施力仍可令轨道明显改变，无回位或普通行星位移限制。

R改为从当前关卡初始配置重开并恢复满血，Shift+R保留检查点恢复（包括当时血量）。输入清理、镜头复位沿用原场景revision路径；不会把受伤后的检查点误当初始关卡。星际转移区半径110、速度≤60；超速反馈复用非实体目标逻辑，不捕获、碰撞或强制减速。

## Level 2 实施契约：BEYOND THE HORIZON

背景：方舟从太阳系出口进行远距跃迁，抵达银河中心附近的游戏化 Sagittarius A*。关卡配置在 `levels/black-hole.ts`，独立命名/出生位置/目标/检查点。方舟(0,0)、初速度(85,0)，黑洞(1300,0)，独立跃迁出口(3100,0)。不设置屏幕物理边界，不假造引力加速奖励。
