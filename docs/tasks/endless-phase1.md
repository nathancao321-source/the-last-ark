# 给 GPT-6.1 Sol：Endless 2.0 第一阶段开发任务

这是未来实施任务书，本轮只提交设计。先阅读 [完整设计](../design/endless-v2.md)，再检查工作分支的实际文件和差异；不要假定其他任务已经实现这里的接口。

## 目标与范围

改变无限模式反复出现“一恒星两行星”的组合，使连续探索10～20块能遇到空旷、流浪行星、孤星、不同成员数单星系、双星、自然碎石群。保留旧世界，保存后回访不能无故恢复被改动的天体。

本阶段只使用既有 star、planet、asteroid 和渲染能力。允许新增组合和配置，不新增黑洞、脉冲星、彗星、空间站、虫洞、卫星、跨块碎石河或新伤害。主线关卡、节点操作、通用物理力律、速度上限、镜头及音乐均不调整。

基线为 `codex/endless-layout-v2` 的 `9a60a7d`，本设计文档位于 `codex/endless-v2-design`。实际开发前确认是否已有更新；从不含本地音乐历史的已发布分支建立 `codex/endless-v3-generation` 或同前缀的独立分支。不要将 `codex/local-soundtracks` 整条历史推送。

## 1. 建立版本隔离（建议独立提交）

保留v1/v2完整生成行为与旧存档默认规则。增加生成器v3，世界版本与存档格式版本分开。新宇宙使用v3，旧宇宙包括后续未访问块仍使用原生成器。

把“选择内容组合→采样合法布局→创建Body”分开，新增轻量描述与配置模块即可，不要重写Universe或物理核心。建议接口职责：

- `sampleRegionWeights(seed, absoluteCell)`：纯函数，初期只提供连续稀疏/普通密度权重。
- `describeLocalStructures(seed, version, key)`：返回稳定ID、家族、成员初态和完整占地；本阶段仍为块内紧凑结构。
- `instantiateStructure(descriptor)`：转换为现有Body；不依赖相机、不消耗全局随机数。

名称可调整；不提前实现完整跨区块大结构框架。材质/布局/组成用各自Seed子流，调纹理不能改变恒星数量。

## 2. 实现组合与合法初态

使用设计文档第5节的8类候选权重作为初始配置。新配置集中管理，输出实际抽样统计。要求有：

- 真正无物理天体的块及连续低密度片区，不只“没有行星但有恒星”。
- 没有主恒星的独立planet，保持自然引力、惯性和蓝金响应。
- 只有一颗恒星，以及1/2/3/4行星的不同组合；3/4行星需通过物理测试后启用。
- 两颗真实star的双星，先不叠加行星；不能只画第二个发光球。
- 独立2～5颗小行星及预算允许的附属碎石；不再每次固定3颗等间距成员。
- 保留已验证三日系统及原星云地标，v3地标共用生成、发现、导航和背景锚点。

每块≤6实体不变；同块多个结构总数也必须≤6。保留80单位净边距及起点安全区，完整占地包括成员碰撞圆。拒绝采样有限次数，失败减少成员或返回空结构并记录原因，不能无限重试或退回相同中心。

初速度从现有 `bodyGravity/fieldAcceleration` 求得。不要只凭 `sqrt(GM/r)` 填多体速度；使用实际软化、距离衰减与加速度，给双星相容的旋转初态。选少数测试通过的参数族，随机整体方向、尺度、成员构成；允许有安全约束，不允许固定位置脚本或每帧恢复轨道。

允许调整**v3实体自身的**半径、密度、引力范围、初态与材质配置，但必须说明与当前尺度的关系；不能改全局速度上限240、节点能力和通用受力规律来让坏初态通过。不把星环作为额外碰撞半径。

## 3. 保存真实改动，形成最小长期探索闭环

这是Phase 1B，可在组合原型验收后单独提交，但正式完成第一阶段不能跳过。

保留≤32块内存热缓存，增加浏览器冷快照存储适配器（推荐IndexedDB）。保存实际位置、速度、稳定化状态、销毁/合并结果与版本。快照写入成功后才可释放唯一状态；读取完成前不能用初态临时替代，再突然切回旧天体。

本阶段可以先保存整块快照，不强制改成Phase2结构数据库。需要记录被移动实体当前位置到来源块的索引，使返回新位置时也能查到；不能只在重新进入出生块时才恢复移动后的对象。

存档清单与冷记录使用一致的快照代次，K/L和重试行为明确；恢复处于暂停、节点技能关闭，沿用原机制。v3单独存档键/格式；不覆盖v1/v2原文本。容器大小检查按真实实现说明，不把字符串长度写成精确字节数。

记录明确磁盘预算与错误路径（设计起点64 MiB/远征，需实测调整）。额度、拒写、损坏、延迟回包、切换世界、保存中断均有测试。到达容量时暂停并使用现有提示解释，不偷偷删历史、不无限增长内存；本阶段无需新设置界面。导出/清理可先用开发工具验证，但面向普通玩家的恢复路径要写明剩余工作。

离线区域冻结后恢复，不按真实时间快进成新轨道。新生成结果独立于加载顺序；运行后的状态受历史影响，两者别混淆。

## 4. 复用渲染与流式加载

只给现有背景增加连续区域密度输入，保留绝对世界坐标、瓦片边缘采样、Worker版本检查和缓存上限。不要重做P1–P5美术，不加入节点携带星云的错误图层。

真实生成和激活不读取相机。不要复制 `updateEncounters()` 的“在当前屏幕右边刷新”到新宇宙；它适合原主线遭遇，不满足本次相机无关的生成契约。

检查邻块预载是否覆盖最大引力半径、实体速度及加载耗时。避免先显示无害星体、下一步突然启用近距离引力。已有spawnPending保留作重载兜底，但不能靠它掩盖高速出生问题。纯视觉碎石始终无实体，不在船前突然变成障碍。

保持加载≤54块、活跃≤325体含方舟；旧主线不进入此逻辑。相机缩远可显示只读远景，不增加整个视野的物理对象数量。

## 5. 自动测试：必须具体验证

| 测试 | 必须验证的结果 |
|---|---|
| v1/v2回归 | 原描述、位置/速度、地标、旧存档与未来块规则不变；未知版本拒读且不覆写 |
| v3确定性 | 同Seed/坐标/版本完全相同；正负坐标、高位坐标、不同查询顺序、相机变化无影响 |
| 内容分布 | 至少32个Seed×16×16块报告家族、成员数、中心分布、空白连续长度、拒绝率；去除地标干预后每类有样本，不能只统计颜色 |
| 多样性回归 | 固定样本中出现0体、独立planet、孤星、1/2/3/4行星、双星、2～5碎石；未放行类型明确标记，不能用删测试冒充完整交付 |
| 安全构图 | 总数≤6，圆盘不重叠，邻边/角安全，安全起点；所有候选失败路径有界且返回合法结果 |
| 真实受力 | 两种节点仍影响所有可受力成员；星体影响方舟，双星彼此受力；未修改真实输入和力律 |
| 运行稳定 | 各启用初态族120秒，选定双星及多行星600秒；无非有限数值、初态导致的碰撞/非预期逃逸、限速长期饱和或碰撞预算耗尽 |
| 连续航行 | 原有物理步与正常控制下跨10～20块，暂停/重试/Rebase正确；检查加载前后速度连续，无隐形施力骤变 |
| 长距离回访 | 推动或销毁对象，超过32热缓存后回到原/新位置，状态一致；不能默默重新生成原对象 |
| 保存一致性 | 读写中断、世界切换、延迟回包、容量耗尽；记录不会串Seed/版本；恢复不部分回滚 |
| 预算 | 三焦点分离及大量访问后实体、热快照、材质/瓦片缓存有上限；冷存储有明确容量行为 |

测试阈值先用基线统计校准并说明理由。不要为了通过断言强行每隔N块放一个指定天体，也不要把纯测试注入位置当作正常飞行通过。

旧布局测试中“v1/v2内容参数完全相同”的断言仍保留在旧版本上；为v3另加测试，而非把旧兼容保护删除。运行 `npm run check`。

## 6. 浏览器与双人验收

在真实浏览器中使用默认Seed20261017和至少另两个Seed，保存开发选点列表；调试跳转只用于构图检查。另做一条从正常起点连续经过10～20块的真实航行记录，不能用瞬移拼接成通关。

对比至少三种状态：远景布局、靠近可交互星体、两节点共同施力。记录帧耗时p50/p95/p99、加载峰值、实体数、质量档位、分辨率、浏览器与机器环境；同条件比较v2/v3，60 FPS为目标而非预填结果。相机平移和缩放不改变生成或受力。

操作验证：双键盘同时移动与开关技能，现有鼠标/手柄入口不回归，暂停恢复、R、K/L、H/J正常。没有真实两人或实体手柄时如实标注；自动双输入不等于真人合作手感验收。

选择至少一个双星接近、一个流浪行星转向和一个碎石清障案例，提供可复现初始Seed/位置/操作或测试控制器。允许外围绕过，不设必须两人按键的隐藏条件。不能仅凭截图宣布玩法成立。

## 7. 提交顺序与交付

建议独立提交：版本隔离 → 组合生成与统计 → 初态稳定验证 → 冷存储/回访 → 浏览器记录与文档。每一步保持现有游戏可启动。

更新README与无限模式说明，列清已实现、未达标、旧世界兼容、离线冻结和存储上限。交付Seed、路线、截图、性能原始记录、实际测试命令和结果。任何实现不满足稳定性时修复或诚实标记未完成，不用禁引力/脚本轨道顶替。

完成后提交并推送独立开发分支，不合并main。**排除音乐文件及包含音乐的本地提交历史**；推送前检查提交范围与文件清单，不只是工作区是否含mp3。本轮授权是这份任务书中的第一阶段，后续大型星域、遗迹和虫洞等等待单独开发。
