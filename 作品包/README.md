# THE LAST ARK · 最后的方舟

> 双人同屏 · 引力护航 · 二维太空合作游戏

## 一、作品解决什么问题

《最后的方舟》把“合作”做成了一道物理题。

太阳将在七十二小时后爆炸并释放灭绝光波。人类最后的方舟没有主引擎，无法自己转向。两名玩家不直接驾驶飞船，而是分别控制一个引力节点：**P1 吸引，P2 排斥**。只有两个人同时理解飞船的惯性、行星的引力和彼此的力场，才能把方舟送过虫洞、太阳系与黑洞。

传统双人合作游戏常用“一个人开门、一个人拿钥匙”的分工。本作希望更进一步：

- **合作是物理必需品**，不是流程上的按钮配合。单一力场很难同时完成加速、转向与制动。
- **把物理直觉变成玩法**。预测线、惯性、天体引力、行星也会被玩家拖动，玩家需要“提前几秒思考”。
- **用叙事包装操作**。引力节点被解释为一个没有身体、只能弯曲时空的高等文明，两根手指般的引力投影成为人类唯一的舵。
- **零外部依赖的完整作品**。星空、地球、方舟、黑洞、星云全部由 Canvas 程序化绘制，音轨本地加载，无服务器、无账号、无外部素材。

## 二、主要功能

### 合作与物理

- 双人同屏，各自独立选择键盘、鼠标或手柄；两名玩家不能共用同一个鼠标/手柄槽位。
- 吸引与排斥两个力场按矢量叠加，同时作用于方舟、行星、陨石等可受力天体。
- 有限加速度、惯性飞行、辅助制动；预测线演算未来最多 12 秒的轨迹。
- 教程会强制玩家理解“吸引—排斥—双场叠加—惯性护送”四个基本动作。

### 内容与进度

- **初次接触**：新手教程，学习移动、吸引、排斥与双场叠加。
- **逃离太阳系**：在太阳引力、日冕与来袭小行星之间规划航线。
- **银河深渊**：绕过黑洞、周期喷流与吸积盘，寻找安全窗口。
- **群星之间**：主线完成后开放的无限星域探索。
- 章节按顺序解锁；三章主线完成后开放**自由回溯**，可重玩任一章节。
- 进度自动保存在当前浏览器，刷新后继续；无需账号。

### 界面与体验

- 电影感封面、动态星空、紫金配色、地球与方舟程序化插画。
- 航行目录展示章节锁定状态、完成进度与推荐下一关。
- 操作设置中文说明，实时显示手柄连接/映射状态。
- 全屏模式、BGM 开关、暂停、检查点重试、全局星图。
- 页面布局适配桌面与窄屏；游戏本体为双人同屏键盘/手柄操作。

### 质量保障

- TypeScript 严格类型检查。
- 当前分支：31 个测试文件、475 项自动化测试通过。
- `npm run check` 会依次执行测试与生产构建。

## 三、必要环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11、macOS 或 Linux |
| Node.js | **20.19+ 或 22.12+**（Vite 8 要求；开发验证使用 Node.js 24.20.0） |

## 四、运行方法

### 开发模式

```bash
npm ci
npm run dev
```

打开终端显示的地址（默认 <http://127.0.0.1:5173/>，端口占用时会自动更换）。

### 生产构建与预览

```bash
npm run build
npm run preview
```

`npm run build` 会先执行 TypeScript 严格检查，再将静态产物输出到 `dist/`。`dist/` 可以直接部署到任意静态文件服务器。

> 不要直接双击 `dist/index.html`。页面使用 ES Module 与本地资源，需要通过 HTTP 服务访问。

### 验证命令

```bash
npm test            # 运行全部自动化测试
npm run test:watch  # 监听模式
npm run build       # 类型检查 + 生产构建
npm run check       # 测试 + 构建
```

### 源码目录

提交作品包时，请将最终源码放入 `源码/` 文件夹。建议包含：

```text
源码/
├── index.html
├── package.json
├── package-lock.json
├── tsconfig.json
├── vite.config.ts
├── vitest.config.ts
├── BGM.mp3
├── src/
├── tests/
├── README.md
└── LICENSE
```

不要放入 `node_modules/`、`dist/`、`.git/`、`.local/`、`cinematics/` 与临时截图。`cinematics/` 是过场动画设计素材，不参与游戏运行。仓库根目录的 `docs/` 为开发记录与设计文档，可按作品包大小决定是否附上。

## 五、操作方式

### 两名玩家

| 玩家 | 默认设备 | 移动 | 技能开关 |
| --- | --- | --- | --- |
| P1 | 键盘 | `W A S D` | `F`（吸引 / 关闭） |
| P2 | 键盘 | 方向键 | `Enter`（排斥 / 关闭） |
| 可选 | 鼠标 | 持续追踪屏幕指针 | 左键开关；右键切换制动 |
| 可选 | 手柄 | 左摇杆 | `A` 开关 |

右上角「操作设置」可为两名玩家分别切换设备。首次使用手柄时，请先在手柄上按一下任意键，让浏览器识别设备；界面会显示“已连接”或“兼容映射”。

### 通用按键

| 操作 | 按键 |
| --- | --- |
| 确认教学提示 / 开始 / 暂停 | `Space` 或手柄 `Menu` |
| 从当前检查点重试 | `Shift + R` |
| 当前关卡重新开始 | `R` |
| 返回航行目录 | `Esc` |
| 全局星图 | `M` |
| 缩放 / 复位 | `−` / `+` / `0` |

## 六、如何现场演示

建议按以下顺序演示，总时长约 5–8 分钟：

1. **打开封面**（<http://127.0.0.1:5173/>）。展示动态星空、地球、方舟与「启程 / 航行目录」；说明作品没有外部图片素材，画面由 Canvas 实时生成。
2. **点击「启程」进入强制新手教程**。让两位玩家分别用 `WASD + F` 与 `方向键 + Enter` 完成“移动 → 吸引 → 排斥 → 双场叠加”。
3. **指出核心机制**：飞船没有引擎，两个玩家只能改变引力；预测线显示未来轨迹。可暂停后重新部署节点，说明“暂停也能规划”。
4. **打开「航行目录」**。展示章节顺序解锁、完成状态与推荐关卡；说明主线完成后开放自由回溯与「群星之间」。
5. **演示一条已解锁的后续关卡**。重点展示太阳日冕/小行星，或黑洞喷流的安全窗口。
6. **打开右上角「操作设置」**。现场把一个玩家切到手柄，展示“已连接”状态与左摇杆操作；再切换全屏与 BGM 开关。
7. **收尾**。回到目录展示进度自动保存；刷新页面证明进度仍在（存储键：`the-last-ark.progress.v1`）。

### 现场建议

- 提前执行 `npm ci` 并启动 `npm run dev`，避免现场安装依赖。
- 提前在本机浏览器完成一次主线，以便目录页直接展示已解锁章节与自由回溯；不要现场清理浏览器站点数据。
- 建议使用 1920×1080 或更高分辨率，演示前按浏览器全屏按钮隐藏地址栏。
- 若现场没有手柄，双键盘即可完成全部演示；鼠标可作为 P1/P2 的另一选择。
- 需要重新演示“首次游玩”时，在浏览器控制台执行 `localStorage.removeItem('the-last-ark.progress.v1')` 后刷新。
- 游戏运行完全离线；如现场网络不稳定，可提前 `npm run build` 并用 `npm run preview` 或任意静态服务器打开 `dist/`。

## 七、技术说明

- **渲染**：Canvas 2D；星空、星云、地球、方舟、黑洞与吸积盘均为确定性程序化绘制。
- **模拟**：固定时间步长、引力场叠加、连续碰撞检测、轨迹预测；教学讲解暂停时不推进物理模拟。
- **输入**：设备无关的意图层，键盘/鼠标/手柄共享同一套物理接口；手柄读取浏览器 Gamepad API，兼容稀疏设备槽与非标准映射。
- **进度**：`localStorage`，键名 `the-last-ark.progress.v1`，无需账号。
- **音频**：本地 `BGM.mp3`，跨菜单与关卡保持同一播放实例。
- **工程**：Vite + TypeScript + Vitest；无运行时第三方 UI 框架。
