# 给 Sol：修复黑洞伽马射线尾端，逐渐收尖、变细并淡出

请直接在现有 THE LAST ARK 项目 `D:\小游戏` 中修改、测试。本任务只修复黑洞上下两极伽马喷流的尾端形态，不重做黑洞主体，不修改太阳波、关卡路线、节点能力或 Endless Mode。完成后提交并推送本次代码和文档，但排除音乐文件；不要合并 main。推送前检查待推送提交历史，不能夹带本地音乐提交。

先阅读当前项目的 `space-vfx-2d` Skill 和实际代码，再看同目录的 **`当前问题截图.png`**。若 Skill 不在当前工作树，先检查已有 Skill 分支，不要假定文档里的 API 都已存在。

## 1. 用户指出的真实问题

截图中，蓝色射流看起来是一根等宽的光条，尾端突然变成一个清晰的圆头。外面虽然还有暗色辉光，但主体仍然像被截断的灯管，而不是自然消散的高能喷流。

用户要的形态非常明确：

> 喷流往远处延伸时，应该慢慢变尖、变细，然后淡化掉。

这里的“慢慢”首先指**沿喷流长度方向的连续变化**，不是仅在 Dissipating 阶段让整根光柱一起变透明。Firing 稳定喷射时，尾端也必须已经具有收束和消散的形态。

## 2. 修改后的视觉目标

- 根部仍然集中、有力，保持当前世界 Y 轴方向。
- 中段是清晰可见的蓝白色高能束流，外围包裹更暗、更柔和的蓝紫色羽流。
- 进入尾段后，轮廓连续收窄，形成细长、柔软的尖端；不要在最后几个像素突然剪出一个三角形。
- 同时逐渐降低亮度和透明度，最终融入背景；最远端不留亮点、圆帽、平切口或一根独立细线。
- 白色内芯、蓝色主体、外围羽流、细丝和粒子都需要服从协调的尾段包络，不能只把白色内芯削尖，而宽大的蓝色胶囊体仍然露出圆头。
- 尖端可以有轻微的等离子体起伏，但不能持续左右甩动，更不能让喷流主轴偏移。
- 上下两束对称地向远离黑洞的方向收尖：上方朝 −Y，下方朝 +Y。

不要通过单纯提高透明度掩盖等宽轮廓，也不要用增大模糊、扩张光晕或把尾部移到屏幕外来伪装修复。

## 3. 已核对的代码入口与排查线索

以下入口在撰写此提示词时确实存在，但执行前请再次核对当前版本：

- `src/render/hazards.ts`：`drawHazards()`。
- `src/game/hazard-geometry.ts`：`JetGeometry`、`JetBeam`、`jetGeometry()`、`jetVisualEnvelope()`、`jetSpatialFade()`、`jetParticle()`。
- `src/game/hazards.ts`：真实伤害和连续暴露处理。
- `src/physics/hazard-collision.ts`：胶囊形危险区的连续接触检测。
- `src/debug/hazard-panel.ts`：危险调试界面。
- `tests/jet-envelope.test.ts`、`tests/hazard-contract.test.ts`、`tests/hazard-timing-regression.test.ts`、`tests/hazards.test.ts`。

当前渲染代码有以下具体线索：

1. 喷流绘制设置了 `ctx.lineCap = 'round'`。
2. 蓝色伤害主体通过固定 `lineWidth` 从局部 `(0, 0)` stroke 到 `(0, jet.length)`；这条路径仍然会形成等宽圆帽。
3. 从 `jet.length` 到 `visualLength` 的装饰尾流也使用了固定宽度 stroke。
4. 白色内芯已经存在局部 taper，但它并没有改变整个蓝色主体的外轮廓。
5. 外侧羽流宽度包含随距离增加的项；只调整轴向 alpha，不能保证外轮廓收尖。
6. 粒子横向摆幅及细丝宽度也要检查：如果它们在尾端仍维持原宽度，就会暴露出一根已变暗但没有收束的光柱。

这些是从源码确认的可疑绘制路径，不是已经完成浏览器逐层定位的最终结论。请实际分别关闭各层，对照截图确认圆头来自哪一层；不要只改 `lineCap` 为 `butt`，那只会把圆头变成平头。

## 4. 推荐实现方式

### 统一空间包络

以权威 `JetBeam.start`、`direction`、`length`、`visualLength` 定义局部轴向距离 `s`。建立可单测的尾段包络，例如：

```text
u = clamp((s - taperStart) / (visualEnd - taperStart), 0, 1)
smooth = u*u*(3 - 2*u)
widthFactor = (1 - smooth)^widthExponent
alphaFactor = (1 - smooth)^fadeExponent
```

这是思路，不是必须照搬的最终公式。请通过实际画面确定起始位置和指数，避免尾端过短、过尖或像匕首。包络应有平滑的起止，有限且不为负，不出现 NaN/Infinity。

将尾段起点、长度、收束曲线、淡出曲线集中配置。空间收束包络与已有 Warning/Firing/Dissipating 的**时间包络**分开，再平滑合成。能量降低、阶段切换时，不应重新长出圆头或突然跳变。

### 用真实变宽的形状绘制

优先使用左右边缘采样点构成连续的二维 ribbon/多边形，或等效的可变宽度绘制方式。不要让固定宽度 stroke 的端帽承担最终尾部轮廓。

纹理和细丝可继续复用现有确定性实现，但横向分布也要受到尾段包络约束。粒子的亮度、横向散布和可见长度应在远端平滑收敛，循环回到根部时不可出现跳点。

无需引入 Three.js、WebGL、新渲染框架或运行时依赖，不要每帧重建复杂纹理。

## 5. 保持伤害与视觉对应，禁止隐形伤害

沿用现有的：

**Gameplay State → Authoritative Hazard Geometry → Collision + Rendering**

这次优先保持现有喷流伤害长度、宽度、周期和玩家逃生空间不变，只改视觉尾段。不要为了画面自然而暗改碰撞体、伤害时序或伤害值。

特别注意：目前危险区是胶囊体。`beam.end` 是末端圆帽的中心，不一定是危险范围的最远边界；最远端还包含 `coreRadius`。请在 Debug Collider 中核对完整边界。

- 在 Firing 期间，实际危险核心必须仍有清晰可辨的视觉覆盖。
- 不能把一段仍然致伤的区域淡到完全不可见，或画得比真实危险区明显更窄。
- 可以先让**内部高亮细丝**逐渐变细，而危险区外轮廓保留必要可读性；再在完整危险范围以外，让较弱的装饰尾流继续连续收尖、淡出。
- 危险核心与无伤害尾流之间通过材质、亮度自然过渡，不要用一个明显的圆头作为二者的分隔标记。
- 装饰尾流不能白亮到与危险核心无法区分，也不能改变权威危险长度。
- 若当前视觉尾长不足以完成自然过渡，可调整集中配置中的**纯视觉尾长**，同步核对裁剪与性能；不要悄悄扩大伤害范围。
- 若发现无法同时满足形态与现有碰撞契约，先在结果中明确指出具体矛盾，不得自行改成另一种伤害机制。

必须保留：世界 ±Y 双向喷流、Warning 无伤害、Firing 才伤害、Dissipating 关闭伤害、每次独立有效暴露扣最大 HP 的 50%、持续接触不逐帧扣血、第二次有效命中可致死，以及事件视界立即失败。

- 根部、主体、尾流、粒子共用同一份喷流世界几何。
- 摄像机平移与缩放只应用一次，不要保存屏幕空间尾端位置。
- 镜头移动不能让尾流与黑洞脱节。
- 使用已有模拟时间，暂停后保持稳定；不要另开墙钟时间驱动尾部。
- 不重新设计当前横向吸积盘、弯曲光带、黑色核心或节点重组动画。

## 7. 必须做的验收

1. 在真实浏览器中对照本目录截图，找到当前圆头/等宽截断的实际来源。
2. 分别检查上、下喷流的根部、中段、尾端，至少覆盖近景和能看见整条喷流的远景。
3. 稳定 Firing 时，外形必须连续收尖，末端亮度融入背景；不能只在最后消散时看起来正确。
4. 观察完整 Warning → Firing → Dissipating → Cooldown，尾部无闪烁、骤缩或圆帽突然出现。
5. 暂停并开启 Debug Collider，截图检查危险范围的可见覆盖；随后关闭叠层检查正式画面，避免调试色掩盖问题。
6. 摄像机平移、缩放后仍保持对齐；粒子不在尾端突然横向散开或跳回。
7. 检查高、中、低画质及高级效果关闭后的必要危险提示；低画质不能退化回明显的等宽圆头尾流。
8. 增加针对尾部轮廓及包络的测试：末端宽度和透明度趋近零、收束区间连续、上下对称、阶段边界平滑、实际危险区可读。
9. 保留并运行伤害/CCD 回归测试，再执行 `npm run check`。不要通过删除真实伤害断言让测试通过。
10. 记录实际浏览器动态观察和性能；静态截图及构建成功不能代替动画验收。没有实测的项目明确标注。
